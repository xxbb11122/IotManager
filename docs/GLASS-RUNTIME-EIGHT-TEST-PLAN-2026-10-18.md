# Glass 项目八项运行时边界测试方案

日期：2026-10-18。目标是对此前默认跳过的八类运行时场景建立可复现的隔离集成证据。保留原有真实环境用例的启用条件，不通过伪造响应将它们改为通过。

## 测试对象与环境

- 实现基线：`c62ded70cb5e09b4966d4552c435869a4dc38850`；执行时同时记录工作流的准确提交。新增内容限于测试工具、测试配置及文档，不更改 code10 APK。
- GitHub 临时 Ubuntu 运行器，独立 Compose 项目 `iot-manager-eight-<run-id>`。本机 Docker/WSL 当前不可用，执行环境选用临时运行器。
- PostgreSQL、Keycloak、Backend、Caddy 使用项目真实代码和现有加固配置；四种角色使用临时测试账号，站点数据均为合成数据。
- AI 使用仅连接内部网络的 OpenAI 协议夹具。Backend 仍通过 HTTPS、主机白名单及受信任的测试 CA 访问夹具；不关闭 TLS 校验，不配置真实供应商密钥。
- 这些原始运行时脚本操作站点 Web 控制台及服务接口。本轮结果不等同于 Glass APK 的真实账号、手机 CA、BLE 或现场 LAN 验收；此前 APK 的 16 项隔离检查另行保留。

## 测试矩阵与通过条件

| ID | 原跳过场景 | 本轮执行方式 | 通过条件 |
| --- | --- | --- | --- |
| R01 | N 写入、N−1 读取并写入 | 实际构建和切换两个 Backend 版本，保留同一个 PostgreSQL 容器和数据卷 | 读取 N 的设备/命令，旧版时间偏差小于 90 分钟；N−1 可新增设备和命令；数据库迁移记录不被回退 |
| R02 | 站点 AI 对话、知识库关闭 | 真实登录、Web、Backend、数据库及 HTTPS 模拟供应商 | 回答显示一致、HTML 文本不执行、供应商仅收到一次请求、Embedding 为 0；知识库接口 404；测试会话删除成功 |
| R03 | OWNER 的 PKCE/API/WebSocket | 复用原运行时脚本 | PKCE 登录成功、受保护 API 200、WebSocket 收到 pong、URL 不携带 access_token |
| R04 | VIEWER 只读 | 复用原运行时脚本 | 读取 200、写入 403 |
| R05 | 四角色与跨站点隔离 | OWNER/ADMIN/OPERATOR/VIEWER 和两个测试站点 | 写入、删除、凭据管理及跨站点结果符合原权限矩阵 |
| R06 | 授权码/刷新令牌重放与退出 | 真实 Keycloak，分开会话测试 | 授权码复用、旧刷新令牌复用、退出后刷新均返回 400 |
| R07 | Edge 凭据轮换/撤销 | 合成 Edge 协议客户端，真实 Caddy TLS 和 Backend | 新凭据握手 101；轮换/撤销后旧凭据不能握手；列表不返回明文令牌 |
| R08 | 千设备与百 WebSocket | 1000 个虚拟设备、100 条真实认证连接、25 并发创建 | 创建 1000 成功；每个连接收到至少 1000 条事件；错误 0；列表含全部设备；归档清理后活跃残留 0 |

R01 包含 write/read 两次测试执行，因此八类场景合计九次 Playwright 测试执行。R08 记录吞吐、创建延迟 p50/p95/p99/max、列表耗时和消息数量；未设置未经业务确认的生产性能 SLA。

## 回滚基线

- N：本轮工作流检出的准确提交。
- N−1：`e0977e77220773182df4e3a73741686cbb87c6d9`，仓库中时间权威改造之前的实际开发提交。
- 当前新增 V20–V28 中的七个迁移为扩展迁移；本轮以这两个明确源码版本检查扩展后的数据库兼容性。
- N−1 只在专用覆盖配置中设置 `SPRING_FLYWAY_IGNORE_MIGRATION_PATTERNS=*:future`。正常部署配置不变。
- 这是开发源码回滚演练，不是两个已批准不可变生产发布的回滚认证。受保护的 `rollback-drill.yml` 及其证据/审批要求保持独立。

## 执行顺序与证据

1. 检查运行器和 80/443 端口；建立本次独立配置、随机账号密码及模拟 AI 密钥。
2. 启动真实集成栈，运行 R03–R07；浏览器和原始 TLS 客户端校验测试 CA。
3. 在内部网络启动 AI 夹具，增加测试域名及专用 JVM 信任库，运行 R02。
4. 运行 R08，保存性能数据与清理结果。
5. 在 N 上写入 R01 标记，构建并切换到 N−1，运行 R01 读取/写入阶段，核对数据库身份及迁移记录。
6. 汇总每一阶段的 JSON，关闭且仅删除本次 Compose 项目的临时卷。任何失败保持失败，不降并发、跳过断言或补造通过记录。

关闭 trace、视频和失败截图，避免登录信息进入附件。公开报告只记录计数、摘要、版本和错误概要；完整输出先检查生成的秘密及 JWT，再作为运行器证据上传。测试方案和最终脱敏报告提交到现有 GitHub PR。

## 结果命名

明确使用“隔离集成通过”“模拟供应商通过”“开发回滚演练通过”。未调用真实 AI、不代表模型回答质量；负载指标仅反映当次运行器；未执行实体设备或生产环境验收。本方案创建时尚未将任何新增场景记为通过。
