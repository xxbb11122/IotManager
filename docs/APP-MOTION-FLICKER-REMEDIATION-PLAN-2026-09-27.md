# App 动画过渡与刷新稳定性修复方案

> 日期：2026-09-27；版本：v1.0
> 输入：[专项复审报告](APP-MOTION-FLICKER-REFRESH-REVIEW-2026-09-27.md)；起始代码 `7675df8`。
> 执行方式：先冻结本方案，再修改实现、增加失败回归、执行验证，最后另交实施结果。
> 范围：客户端、客户端构建身份和相关 CI；不变更后端协议、设备命令语义、发布审批、真实设备数据。

## 1. 完成目标与不可退让边界

本轮不是扩大动效数量，而是修复已复现的交互/更新缺陷。完成条件为：相同数据不产生无效更新；同页面保留关键 DOM 节点；一次事件最多一次表现；正在进行的操作不会被推送改为相反命令；失败重连不触发密集快照请求。

不得通过关闭 WebSocket、停止必要回执查询、隐藏失败、全局关闭动画、放松权限或删除缓存来让检查变绿。权限撤回、连接失效、真实 ACK/失败仍及时生效。物理手机录屏、实际 APK 安装、WebView/系统生命周期和性能长稳不在无设备条件下虚报通过。

## 2. 固定修复决策

| 工作包 | 对应问题 | 实现决策 | 验收重点 |
| --- | --- | --- | --- |
| FIX-01 数据去重 | UI-01/05 | Store 对规范化状态做值相等判断，相同状态不发布；客户端本地状态相同也不入渲染队列。计数记录抑制结果 | 连续相同 device/weather/command 事件不再触发 UI 补丁 |
| FIX-02 稳定区域 | UI-01/03/05 | 详情标题、连接、状态、控件、天气/预报、冷却按钮改为稳定键协调；仅结构真的变化时增删节点。DOM 协调记录实际变更 | 控件/区域引用不变；开关同节点经历样式过渡；输入/选区/滚动保留 |
| FIX-03 输入意图 | UI-02 | 按下时记录命令目标、作用域和参数；点击前核对。目标变更或安全条件失效就明确取消，不静默改参；相同状态推送不打断正常点击 | 鼠标和可信触摸均不丢合法点击；按下开启不能松开提交关闭；禁用立即有效 |
| FIX-04 合并与动效 | UI-04/05 | 同一协调批次合并设备/命令/连接对同一区域的重复操作；天气反馈收敛为稳定更新时间标记的局部提示，不再整片淡入；重复事件不重播 | 单批一次控件补丁；天气变化最多一次提示；预报更新不重新播放天气动画 |
| FIX-05 刷新调度 | UI-06 | 快照请求按端点/站点/会话 single-flight；自动读取以最近尝试计 120 秒冷却，成功和失败均计入。保留主动刷新 60 秒冷却与天气缓存策略 | 首次失败后的 WS 连接不追加同轮请求；短时间反复重连不穿透冷却；上下文隔离 |

## 3. 渲染与动画细则

1. 相同原始事件可以被传输接收，但同一规范化状态不能持续发布。对象字段顺序不同不应误判为变化。
2. 同一实体同页面的开关、range、文本输入、按钮和关键区域保留节点；安全状态允许必要的内容增删或禁用。
3. 普通遥测 1Hz 只约束可见补丁，不减损数据接收；含状态、连接、reported/desired 控制状态变化的事件走优先路径。150ms 仍用来合并普通交互短突发，不冒充长期限频。
4. 设备+命令+连接在同批出现时，一次设备详情更新已处理的控件不再被后续域重复处理；命令信息和活动自身仍更新。
5. 天气区域不因预报或同戳重复数据更换节点。新天气反馈只在更新时间等局部位置表现；数据区域保持可读。
6. reduce/后台策略取消装饰动画，但不改变最终状态、命令参数和读取次数。

## 4. 操作意图和安全规则

- 捕获范围为设备命令操作；按下记录目标数据与当前 scope/view。
- 松开/点击时若节点仍是同一意图且可操作，则正常执行一次。
- 若数值、实体、站点、账号、视图或权限已变化，取消这次旧意图并提示重新确认，不擅自执行旧命令，也不执行新反向命令。
- pointercancel、导航、销毁、隐藏和多指中断有明确回收路径；键盘/辅助技术产生的无指针点击仍按当前可用目标执行。
- 自动化必须同时证明：相同数据不会吞点击；真实变化不会误发；关闭/只读不能被保护机制绕过。

## 5. 请求合并规则

同一 endpoint/site/session 的列表请求只运行一个；重复入口共享它。首次启动/手动刷新/切换上下文允许主动读取，但同样记录尝试时间。自动重连和后台恢复读取检查该时间，120 秒内不重复启动；失败也受限制。新上下文不继承旧上下文的冷却或结果。

请求去重不等于显示“已经最新”：失败仍显示已有缓存/错误，冷却仍显示未取得新数据。天气主读 10 分钟、预报 30 分钟缓存以及下拉 60 秒冷却保持现有语义。

## 6. 回归矩阵

| 编号 | 必测场景 | 通过条件 |
| --- | --- | --- |
| R01 | 重复设备/天气/命令事件，含字段顺序变化 | 无额外发布，无无效 DOM 变更 |
| R02 | 遥测中途按下/松开，鼠标和可信触摸 | 相同状态执行 1 次；状态反转时取消，0 次反向命令 |
| R03 | 开关 off/on、ACK、pending、readonly | 节点稳定；普通模式发生真实过渡；只读及时；reduce 无动画 |
| R04 | 天气+预报连续/同批补丁 | 稳定节点、至多一次局部提示，表单草稿和水平阅读位置不变 |
| R05 | 同一命令回执重复、设备和命令同批 | 不重复控件补丁，命令结果及时准确 |
| R06 | REST 失败且 WS 多次重连、请求仍在途 | 冷却不穿透，single-flight，切上下文后结果不串用 |
| R07 | 持续遥测、紧急命令/连接变化、后台累计 | 展示限频，优先更新不等一秒，恢复只处理最新快照 |
| R08 | 现有导航/离线/下拉/焦点/预览测试 | 原有相关用例继续通过，新故障模型纳入必跑 |
| R09 | 构建和版本身份 | Web 生产构建通过；无开发预览泄漏；build-info 与界面可核对 |

## 7. 执行与交付顺序

1. 数据相等与请求门闩等纯逻辑模块及其单元测试。
2. 稳定 DOM、按压意图、批次合并、局部动效和诊断计数。
3. 构建身份、CI 必跑清单、故障浏览器回归。
4. 执行客户端单元测试、指定浏览器套件、生产构建和隔离检查；失败先定位并修正。
5. 交付实施结果：已改文件、实测数字、未关闭项。必要时说明本机 SDK/设备限制，不用 Web 通过替代实机通过。

本轮不自动提交 GitHub、不安装到手机、不更改签名密钥。需要新版 APK 时，在确认 Android 工具链可用后另行构建并提供哈希；App 中的构建身份能力先落地。
