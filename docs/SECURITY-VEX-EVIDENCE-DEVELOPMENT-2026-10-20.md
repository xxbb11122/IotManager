# 漏洞适用性证据与 VEX 开发说明

本变更落实失败整改方案第 3.5 节。扫描门禁仍阻止没有有效批准的 HIGH/CRITICAL；没有预置任何生产例外或虚构审核人。

## 决策类型

版本 1 保留 `affected-but-accepted`，要求风险原因、补偿措施、批准和期限。

版本 2 仅接收 `not_affected`、`fixed`，不混用风险接受语义。必须绑定 CVE、artifact、精确镜像 digest 和源码提交；必须提供不同于编写者的审核人、独立 GitHub 评审链接、批准时间、有效期和跟踪记录。

证据位于 VEX 目录以内，以相对路径和 SHA-256 引用。解析器解析真实路径，拒绝目录穿越及指向目录外的链接。每份 JSON 证据必须再次匹配源码、digest、CVE 和结论，包含全部通过的具名检查及上游参考；`fixed` 还要求修复提交和已验证的祖先关系。

`validate-vex` 验证版本 2 时须传入 `--source-sha`。镜像扫描命令使用候选清单中的源码提交。错误摘要、错误源码、被修改的证据、无批准、自己批准、过期、未来批准和失败检查均拒绝。

## 批准边界

字段校验只验证记录结构与证据完整性，不向 GitHub 证明审核人的权限、评审内容或独立性。评审链接也不自动证明有人完成评审。真实批准仍须由受保护仓库评审及发布流程核实，不能仅填一个用户名或链接获得正式发布资格。

测试中的作者、审核人及链接都是合成夹具，不可复制为生产批准。实际 `security/vex` 没有新增已批准记录。未取得独立审核的适用性分析应作为草稿留在测试报告中，门禁继续 FAIL。

## 验证与复查

新增 `scripts/ci/tests/vex-evidence.test.mjs` 并接入 Quick CI；原版本 1 发布契约回归保留。新增 Spring 上下文测试在 AI/知识库启用时枚举实际业务映射、检查视图与路由 Bean、探测 MCP/SSE 路径并验证 JSON/SSE 协商。它提供已测试配置的适用性证据，不等同于所有部署和未来路由的永久豁免。

部署配置、依赖、源码或镜像摘要变化后需要重新生成证据与审核；不能复用旧 digest 的结论。
