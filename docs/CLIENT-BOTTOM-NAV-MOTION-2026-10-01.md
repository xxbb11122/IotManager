# 客户端底部模块选择动效方案与审核

> 日期：2026-10-01。范围：移动端底部主导航“设备 / AI / 动态 / 添加”。桌面侧栏、页面路由与业务请求沿用现有机制。

## 方案

1. 底栏保持四等宽入口、至少 48px 点击高度和安全区留白。单个浅青色选中底板位于按钮背后，以 `transform` 在四个入口间移动，使用现有 `--motion-page`（200ms）和 `--ease-enter`。选中颜色与图标上移 2px 使用 `--motion-feedback`（150ms）。
2. 同级切换时，页面内容沿用现有 200ms 淡入。点击立即切换路由及 `aria-current="page"`，底板只表达已选页面，不承担业务等待或锁定点击。快速连续点击直接转向最新入口，同项重复点击不重播。
3. 首次挂载将底板放在当前入口；AI 历史与性格子页继续高亮 AI。其他二级页面沿用当前“不选中主模块”的语义，底板淡出；返回主模块后显现。
4. `prefers-reduced-motion`、应用降级或后台隐藏时沿用全局动效策略，直接显示最终选中位置，保留颜色、边框、焦点和语义。

## 实施前审核

| 检查项 | 现状与结论 |
| --- | --- |
| 入口数量 | 当前已有四个入口，底栏 CSS 仍是三列；应先修正为四等宽，否则动效位置无法对应按钮。 |
| 动效归属 | App 壳层及底栏 DOM 在常规路由中保留；可只更新选中状态和底板偏移，避免重建或定时器。 |
| 打断与重绘 | 用 CSS transform 过渡到最新偏移；业务点击即时处理，数据补丁不改选中值。 |
| 可访问性 | 保留 48px 点击区及现有 `focus-visible`；用 `aria-current="page"` 明确当前模块。 |
| 减少动态效果 | 现有媒体查询与 `data-motion="reduced"` 会将过渡时长归零；底板不依赖动画结束事件。 |
| PDA 与布局 | 底板只在四列网格内移动，保留顶部边框、安全区和窄屏布局；不增加常驻 `will-change`。 |

审核结论：方案符合现有导航和动效规范，可以实施。验收重点为四列几何位置、快速切换与重复点击、AI 子页、减少动态效果、键盘焦点和 320px 窄屏；Android/PDA 实机手感仍需设备验收。

## 实施与验证

- `client/src/css/style.css`：四列底栏、单个可平移选中底板、150ms 图标反馈；底板显式使用 `border-box`，使带边框的位移距离与网格列宽一致。
- `client/src/js/ui.js`：只同步主导航按钮；立即更新选中 class、`aria-current="page"` 与底板偏移，AI 子页继续归属 AI。底栏 DOM 在路由和数据重绘时保持稳定。
- `client/e2e/bottom-navigation-motion.spec.js`：四列布局、AI 子页、连续切换、底板几何位置、节点稳定、320px 点击区与减少动态效果均通过。首次浏览器检查发现带边框底板每格多移 2px，修正盒模型后复验通过。
- 相关回归：`ai-workspace.spec.js` 6 项与 `mobile-client.spec.js` 1 项通过；Vite 生产构建与开发态预览隔离检查通过。
