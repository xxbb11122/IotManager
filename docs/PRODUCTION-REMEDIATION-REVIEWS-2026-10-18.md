## 方案审核

对象：[整改方案](PRODUCTION-REMEDIATION-PLAN-2026-10-18.md)。审核在开发文档编制与产品代码修改之前完成。

| 问题 | 初审结论 | 最终处理 |
| --- | --- | --- |
| 仅调整 TZ 能否修复八小时时差 | 不通过；两代 JVM 已同为 Asia/Shanghai | 改为核查全局 JDBC Calendar 转换；必须比较数据库实际列值和独立旧读取 |
| 将 v3 库称为原旧 APK 可回退 | 不通过；已安装旧二进制不能追溯修补 | 明确需要重新构建兼容旧业务包，保留同签名、包名和递增 versionCode |
| 移除 UTC 配置是否破坏 Instant | 有条件通过 | 开发文档必须加入跨 JVM/数据库时区的绝对时间断言，保留注入式 UTC Clock |
| 代码修复是否顺便修正全部历史行 | 不通过；缺失 UTC 的旧行含糊 | 此次只读差异核对，禁止自动回填和修改既有 Flyway 校验和 |
| Vite 主版本升级抬高最低浏览器 | 不通过 | 固定原构建目标，四端浏览器回归；版本与漏洞使用官方信息复核 |
| 缺签名、runner、实机时可否认定上线通过 | 不通过 | 代码开发与真实发布验收独立记账；外部缺项始终 NO-GO |
| 自动修改管理员保护和密钥 | 不通过 | 实现只读预检、受保护签名入口与配置要求，不擅自改权限或生成正式密钥 |

复审结论：上述问题已纳入方案修订，**方案设计通过，允许编写开发文档**。该结论不代表实际测试通过或发布批准。

## 开发文档审核

对象：[开发文档](PRODUCTION-REMEDIATION-DEVELOPMENT-2026-10-18.md)。逐条核查实际目录、现有构建方式和授权范围后，发现并修正如下事项：

| 项目 | 审核发现与修正 |
| --- | --- |
| 时间测试 | 仅 ORM 写后 ORM 读会对称抵消时差；必须增加旧 JDBC 独立读及数据库列值断言 |
| Android 回退 | 不能只验证 JS 打开成功；生成包必须给出新 code、同包名/证书要求与未签名状态，安装验收另列 |
| schema 安全 | 无版本打开后必须验证版本、store 与索引；不能把任意 VersionError 转为成功 |
| 签名来源 | 任意 SHA + secrets 存在代码泄露风险；限定受保护默认分支历史、环境审核，且签名前先执行仓库保护预检 |
| 构建兼容 | 固定原浏览器目标并验证四端，不能依赖 Vite 新默认值 |
| 验收证据 | API 无权限不是保护存在；预检 UNKNOWN 返回非零。实机、生产恢复和签名缺项不记 PASS |

复审结论：上述约束均已写入开发文档，**开发文档设计通过，允许按文档实施**。实现验证及最终上线判断将在交付报告独立记录；不会把自审当作外部审核批准。

## 实现期间追加审核

- 回退补丁只按 import/版本特征匹配仍可能接受未审旧实现；改为校验冻结的 v2 源文件规范化 SHA256，未知变体拒绝生成。
- Android 新 code 只比较仓库默认值不足以证明高于已分发版本；增加保护环境中维护的最高分发 code，缺失也失败。
- 默认 GITHUB_TOKEN 可能无权读取 runner/环境治理；明确只读预检 token 配置，保持 API 错误失败关闭。
- 明确 Play App Signing 的分发证书可能与 AAB 上传证书不同，验收单按实际分发渠道记录。

以上修正已同步开发文档和实现，设计层面没有未处理的阻断问题；外部验收仍按 PENDING 管理。
