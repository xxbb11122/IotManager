## 1. 实施内容

| 方向 | 已实施内容 |
| --- | --- |
| 全局视觉 | 中性画布、统一文字和边界、8–10px 常规圆角、较轻间距；普通内容与按钮使用不透明表面，导航保留少量玻璃效果 |

| 设备更新 | 一次建立列表索引，按设备引用匹配；识别实际顺序变化，增删重排保留可复用节点；空列表恢复完整空状态；被删除行失去焦点后转到添加入口 |
| 异常标识 | 重复或缺失主标识的设备仍保留独立行，但暂停打开入口并说明原因，避免进入错误的设备控制页 |
| 材质同步 | 普通内容变化不再触发导航材质全树同步；保留导航、材质、尺寸、系统对比度和前后台变化的同步及清理 |
| 更新时延 | 非遥测数据改为约一帧（16ms）合批；保留纯遥测原有 150ms 初始合批与后续约 1 秒最新值呈现 |

没有改变后端协议、数据库或设备命令类型。运行页面仍使用正式客户端适配器；合成设备和请求替身仅存在于测试及性能脚本。

## 2. 与原方案的具体调整

初步生产测量显示，首页一次设备更新的总响应包含入口显式配置的 150ms 等待。减少光学组件和索引优化能降低计算量，但这个等待仍占据主要时延。因此保留同一协调器及突发合并机制，把**非遥测**更新窗口缩为 16ms，连续遥测仍保持原有呈现节奏。相应单元测试验证新窗口可抢占延后的遥测，且同批只呈现最新状态；权限、命令和操作取消没有新增节流。

首次对照发现主入口仍传入旧值，覆盖了新的默认值。已修复入口并重新构建；早期 `comparison-20261110/`、`comparison-final-20261110/` 是中断的诊断结果，不作为最终验收数据。

- 改前构建保存在 `artifacts/glass-comprehensive-20261030/baseline/production/`；对应源码清单、SHA-256、已跟踪文件补丁和未跟踪 AI 样式均已保存。

- 两个构建均由本地静态服务器提供，Playwright 只允许测试服务器资源；API 和 WebSocket 均使用固定合成数据。外部请求、异常脚本、意外写请求及样本失败会使测量失败。
- CPU 原速和 4 倍限速分别记录；前后交替测量，每轮使用新的浏览器上下文模拟冷启动，不声称清空宿主系统缓存。
- 本地输出沿用方案目录名 `20261030`，本轮执行日期以报告内时间和本文件日期为准。

首批设备与批量更新满足“降低至少 10% 且至少 2ms”的原定目标。改善包含光学层减少、列表与观察器优化，以及非遥测合批窗口从 150ms 缩短为 16ms；不能将全部收益归因于 CSS 或 GPU。

**导航补测：**4 倍首测存在明显阶段波动，未直接认定通过。按[预先记录的补测规则](../artifacts/glass-comprehensive-20261030/navigation-retest-20261110/retest-policy.md)，追加三轮相同设备数量和热更新/导航序列，不增加点击间隔；单独重建热页面，省去其他上下文中的冷加载批次。补测三轮 p95 中位数为 126.0→124.7ms；保留首测、合并六轮后为 **122.7→117.0ms**（前后各 180 个点击样本），低于原有容差上限 128.835ms。该环境下的导航回归门槛通过，**4 倍限速导航改善幅度仍不确定**，不作显著变快的承诺。原始失败及各轮值均保留在[导航验收汇总](../artifacts/glass-comprehensive-20261030/navigation-retest-20261110/acceptance-summary.json)。

固定三次 1000px / 2 秒滚动，按三轮总数的中位数比较：原速前后均无长任务；4 倍限速由 8→5 次、1438→633ms，通过“不增加”门槛。滚动帧间隔 p95 中位数为原速 33.4→16.7ms，4 倍限速 50.0→16.8ms；候选版本在限速压力下仍有长任务，不称为完全无卡顿。

**边界场景：**0 / 50 / 1000 台各为单次边界采样，不作为 p95。改后原速首次容器可见约 148.7 / 219.5 / 511.6ms；4 倍限速约 794.7 / 996.0 / 2598.3ms。50 与 1000 台均完成 20 台更新，普通列表光学子节点均为 0，呈现设备数与合成数据一致。

首次主测量进程在旧版 1000 台、4 倍限速场景等待实时通道就绪时超时退出；200 台主场景的完整样本已保存，剩余边界没有按通过处理。随后[独立边界补测](../artifacts/glass-comprehensive-20261030/boundaries-reviewed-20261110/results.json)完成两版的六个限速边界，旧版该点首次可见约 43.99 秒，改后约 2.60 秒。原超时仍记录于[首次主报告](../artifacts/glass-comprehensive-20261030/comparison-reviewed-20261110/results.json)，不能从单个边界点推导生产稳定性。

每轮 min/max、p50/p95、全部输入样本、错误和光学节点数见[原始主报告](../artifacts/glass-comprehensive-20261030/comparison-reviewed-20261110/results.json)及[首次门槛汇总](../artifacts/glass-comprehensive-20261030/comparison-reviewed-20261110/acceptance-summary.json)。首次汇总保留失败状态；后续补测单独记录，不覆盖原始失败。

测量使用 Chromium 151.0.7922.34、Node 22.23.3、Windows 11、AMD Ryzen 7 7735H，390×844 CSS px，减少动画，单浏览器进程。电源方案为平衡，采集时电池 99%、状态码 2；[电源记录](../artifacts/glass-comprehensive-20261030/comparison-reviewed-20261110/power-environment.json)保留原始值。主机其他应用和系统调度没有受控；4 倍限速是 Chromium CPU 模拟。

冷启动每轮 30 个新浏览器上下文；热更新先预热 5 次，再各测 30 次单设备、20 台批量及导航。每档 CPU 各三轮，前后交替。p95 使用最近秩法，验收比较三轮 p95 的中位数，不将所有样本混在一起选最优值。状态更新口径是模拟事件注入到目标 DOM 文本就绪；批量中包含视口以外的设备行，不等同于所有设备已经在屏幕上绘制。两次 `requestAnimationFrame` 仅作为绘制机会代理。

### 4.3 命令、安全状态与 AI 压力对照

前后两版、两档 CPU 各完成三轮；每个时延指标每轮预热 5 次、正式测量 30 次。以下为三轮 p95 的中位数，单位 ms，单元格各对应 90 个样本。

| 事件到 DOM 反馈 | 原速改前→改后 | 4 倍限速改前→改后 | 判定 |
| --- | --- | --- | --- |
| 命令 ACK 确认 | 167.1→20.8 | 402.4→147.5 | 通过 |
| 命令失败 | 169.0→20.6 | 440.0→170.9 | 通过 |
| AI API 返回 403 后清理内容 | 3.8→1.4 | 27.3→7.3 | 通过 |
| 设备读取失败后进入缓存只读 | 141.1→28.4 | 256.0→92.3 | 通过 |

采用基线加 max(2ms, 5%) 的回归容差，8 项时延门槛全部通过。命令从模拟实时事件注入开始计时；403 从浏览器收到拒绝响应开始；离线从设备读取请求拒绝开始，到缓存只读控件与提示就绪。网络与模型生成时间不包含在这些 UI 反馈指标中。

AI 历史由生产 API 的分页请求逐页读取，按请求的 20 条大小提供合成页，上限保持 100 条。分别加载 100 和 500 条消息后，预热 5 次并测 30 次草稿输入。下表每格为 DOM 响应 / 两次绘制机会代理的 p95，单位 ms。

| 历史规模 | 原速改前 | 原速改后 | 4 倍限速改前 | 4 倍限速改后 |
| --- | --- | --- | --- | --- |
| 100 条 | 1.1 / 34.4 | 1.0 / 34.2 | 5.7 / 34.6 | 4.9 / 34.5 |
| 500 条 | 1.4 / 34.7 | 1.4 / 34.5 | 8.4 / 34.4 | 7.2 / 34.3 |

两版均已包含上一轮的草稿局部更新；本轮没有证据证明 AI 输入绘制代理时间显著改善。各轮 30 次合成输入各创建 30 个元素，保持同一输入与消息节点、光标、焦点和阅读位置，输入期间无写请求。另保留真实模块中 100 条消息、20 次按键创建 20 个元素的回归；中文组合事件在 500 条用例中单独验证。

正式工作流的 12 组轮次全部完成，无失败、超时、意外写请求或外部请求；相同设备事件不产生 DOM 变更、节点替换和额外网络读取。模拟后台期间不呈现中间更新，恢复呈现最新值。纯遥测的 1Hz 节奏另由单元与浏览器回归覆盖。
