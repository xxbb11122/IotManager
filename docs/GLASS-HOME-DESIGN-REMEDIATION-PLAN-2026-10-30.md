# Glass Next 设备首页视觉与性能整改开发方案

日期：2026-10-30  
状态（2026-11-10 更新）：历史首页提案，已扩展为[综合整改方案](GLASS-APP-COMPREHENSIVE-IMPROVEMENT-PLAN-REVIEW-2026-10-30.md)并实施；验证与复审见[交付记录](GLASS-APP-COMPREHENSIVE-IMPLEMENTATION-REVIEW-2026-11-10.md)。下文保留原方案范围。  
范围：`apps/client-glass-next` 的设备首页；先完成一页，确认设计方向后再扩展到其他页面。

## 1. 要解决的问题

当前首页同时使用大面积彩色渐变、玻璃滤镜、高光描边、阴影和大圆角，普通按钮、设备行、背景和导航的视觉权重相近。首屏有较多留白，离线快照、实时连接和站点状态分散展示，设备内容被推到下面。

整改目标：保留少量 Glass 质感，让设备信息、连接状态和主要操作更容易被看到；**性能优化和可量化验收是本阶段必达要求**。不重写功能、不改变安全判断，也不以新增功能替代视觉整改。

观察依据为源码和桌面浏览器的未登录、无设备预览；页面在多设备、手机、文字放大和异常状态下的最终表现，需要实施后用合成数据复核。

## 2. 范围与边界

### 本阶段包含

- 设备首页背景、标题、站点信息、连接状态、刷新与添加入口、设备列表和空状态。
- 首页出现的导航、页头在本页面的视觉协调；共有组件使用首页作用域，不能无意改变其他页面。
- 保留当前 `liquid`、`frosted`、`solid`、高对比/强制颜色和减少动画能力，收敛首页普通内容的光学层。
- 对设备首页执行桌面和手机尺寸的浏览器模拟与视觉复核。
- 对首页渲染、更新与滚动建立量化基线，优化实际热点，并按第 8 节进行前后对照；不能只调整 CSS 后宣称性能提升。

### 本阶段不包含

- 设备详情、AI、动态、添加设备、启动页及旧 Client 的整体视觉改版；它们列为后续阶段。
- 后端接口、设备能力、站点权限、BLE、命令下发、实时连接、离线数据或 AI 的业务逻辑调整。
- 修改默认安全策略、抹去离线/只读提示、把模拟数据描述为真实设备、改动用户已保存的数据。

## 3. 设计方向

关键词：**安静、清晰、紧凑、可信**。画面以设备为中心，材质服务于导航，不让材质成为内容本身。

### 3.1 视觉规则

| 项目 | 当前问题 | 本阶段目标 |
| --- | --- | --- |
| 背景 | 多层蓝绿、蓝和暖色径向渐变 | 首页内容区域用低饱和中性浅色；减少色彩渐变和大范围光晕 |
| 表面 | 数据行、普通按钮、面板均叠加玻璃滤镜、内高光和阴影 | 主要内容使用不透明或近不透明表面和细分隔线；导航与必要浮层保留轻玻璃 |
| 圆角 | 内容行与卡片普遍为 18px | 普通内容面板建议 8–10px，按钮约 8px；导航保留适度圆角。尺寸是初稿，依据页面实际视觉调整 |
| 阴影 | 多层组件重复投影 | 列表和普通按钮不使用明显投影；浮层仅保留轻阴影 |
| 层级 | 操作、状态、数据的材质相似 | 页面主操作、状态提示、设备内容分别有清晰层级；警告由语义状态而非炫光突出 |
| 密度 | 设备行最小 116px、内边距 20px；信息稀疏 | 手机和桌面优先使用连续的单列列表与分隔线；桌面限制内容宽度，不为填满屏幕拉大卡片 |
| 触控 | 需保留原有 48px 最小高度 | 单独操作入口保持至少 48 CSS px 的触控目标；文字缩放时不裁切 |
| 动画 | 部分组件进入及状态变化使用动画 | 保留必要的短反馈，移除首页纯装饰性闪光；减少动画设置立即生效 |

建议配色初稿：背景 `#F4F6F7`、内容 `#FFFFFF`、主文字 `#1D292E`、次要文字 `#51616A`、主操作 `#246875`。在纯白背景下，后三者的计算对比度分别约为 14.91:1、6.43:1、6.34:1；实际半透明层、状态色和所有文字组合必须以渲染结果重新测试，不能直接沿用这些数值作为验收结论。

### 3.2 首页结构草图

```text
┌────────────────────────────────────────────┐
│ 站点名称                  连接设置  登录/账号 │
│ 简洁天气摘要                         连接方式 │
├────────────────────────────────────────────┤
│ 我的设备                         添加设备    │
│ 站点 / 空间              [刷新]             │
│                                            │
│ 连接异常：实时状态可能过期   [重连]          │
│ 离线快照：最后同步时间，平台控制只读         │
│                                            │
│ 已认领设备  8                     在线 6    │
│ 设备名称       状态、连接方式         进入 >  │
│ 设备名称       状态、连接方式         进入 >  │
│ 设备名称       状态、连接方式         进入 >  │
└────────────────────────────────────────────┘
```

草图说明信息顺序，不预设必须将两条不同含义的提示压成一条。正常状态不显示空警告，异常时清楚保留：数据过期、最后同步时间、实时连接异常和控制只读各自的事实与操作。状态不能只靠颜色区分。设备列表显示已有真实字段，不编造更新时间、数值或状态。

空状态应是一块简洁区域，保留“添加设备”入口；加载中、加载失败、已成功加载但无设备必须区分。不可为了视觉简洁将加载中显示为零设备。

### 3.3 屏幕适配

- **手机/PDA：**以 320、360、390、430 CSS px 宽度验证，单列展示；支持安全区、长设备名、竖横屏与至少 200% 浏览器文字放大；不允许页面级横向溢出或底栏遮挡内容。
- **桌面：**以 820、1024、1280、1440 CSS px 宽度验证；以单列列表为初稿，过宽屏幕限制正文最大宽度，避免大面积空白和行过长。额外检查 767/768、819/820 CSS px 以及列表容器接近 44rem 时的临界宽度，确认现有视口和容器双列规则均被首页单列规则覆盖，文字放大时也不突然切列。
- **无障碍：**正文目标不小于 16 CSS px，辅助信息尽量不小于 14 CSS px；普通文字对比度至少 4.5:1，大字至少 3:1；焦点清晰可见，键盘操作顺序合理，状态有文字/图标。CSS px 与 Android dp 不可直接等同，原生实际尺寸另行验证。

## 4. 开发设计

### 4.1 控制影响范围

`liquid.css` 中 `body` 背景、`.surface` 和 `.button` 的规则覆盖多个页面；`glass-surfaces.js` 也会为通用类名自动插入光学层。本阶段不能只修改这些全局规则，否则首页整改会同时影响详情、天气和 AI。现有 `glass.css` 的视口双列规则与 `glass-layout.css` 的容器双列规则都需检查；首页作用域内应明确让两者不会冲突。

1. 给首页内容或应用根节点设置明确的首页作用域标识，并在切换页面、局部刷新和前后台恢复时保持一致；不依赖将页面状态写入持久存储。
2. 在作用域内覆盖首页可见画布、设备行、空状态、普通按钮、状态提示；对共享页头和导航只在首页作用域中调整。`body` 的全局渐变会露在桌面内容两侧，因此只改有最大宽度的内容区不够，需用首页专属根节点/外壳状态覆盖整个可见画布；切到其他页面及时恢复原背景。启动遮罩及其他页面先保持现状，并检查首帧过渡不出现异常闪屏。
3. 对首页设备行和普通按钮，避免创建或显示不必要的 `liquid-glass` 装饰层。`addGlassSurface` 常在节点挂载前运行，不能仅靠 `closest()` 查找首页祖先；应在首页构造和局部更新时传入或设置明确的上下文，再验证普通节点不会误伤其他页面。若只靠 CSS 隐藏而底层仍创建光学元素，要明确其性能收益不能由样式推断。
4. 保留 `data-glass`、用户选择、系统强制颜色和高对比度的降级行为。新首页作用域必须能在三种材质间切换，返回其他页面时不得遗留首页样式。
5. 保持 keyed 局部渲染、焦点、滚动位置和原有 `data-region` / 动作标识，避免视觉调整导致设备刷新、导航或事件绑定回归。

### 4.2 预计修改文件

| 文件 | 预计工作 |
| --- | --- |
| `apps/client-glass-next/src/css/glass-layout.css` | 首页列表密度、页边距、排版、设备行和断点；首页作用域内覆盖 |
| `apps/client-glass-next/src/css/liquid.css` | 将首页普通内容的多层玻璃效果按作用域收敛，保留其他页面和材质降级 |
| `apps/client-glass-next/src/js/appearance/glass-surfaces.js` | 仅在确认可安全识别首页内容后，缩减首页不必要的光学节点；需保留其他组件行为 |
| `apps/client-glass-next/src/js/ui.js` | 必要时调整首页结构、作用域、状态区布局；保留动作、状态条件、访问性标签和局部更新标识 |
| `apps/client-glass-next/src/js/appearance/glass-appearance.js` | 在测量支持时缩小观察和同步范围，保留材质、导航、可见性与清理行为 |
| `apps/client-glass-next/src/js/render-coordinator.js` | 仅在性能证据表明必要时调整；严格保留优先级、合并和安全状态语义 |
| `apps/client-glass-next/e2e/`、`test/` | 复用现有测试，补充能验证新增首页行为和布局的必要用例 |

可根据实现增加独立的首页样式文件，但应在现有导入顺序中明确生效位置。当前 `liquid.css` 在 `glass-layout.css` 后加载，且部分规则含 `#app:not([data-glass='solid'])`；仅修改前者可能无法覆盖后者。不要复制整套全局 CSS，也不要为本阶段改写旧 Client 或 Android 原生工程。

### 4.3 状态与交互契约

- 保留添加、刷新、站点切换、登录、设备进入、天气入口、实时重连和下拉刷新；可见布局变化不改变动作含义。
- 实时连接故障、离线快照、同步中、数据过期、登录失败、权限不足、无设备、加载失败各自保留可辨识反馈。多个状态同时出现时不得相互覆盖。
- `BLE_LOCAL` 与平台访问的既有只读判断、命令 ACK/未确认语义不变；本阶段不改命令执行及网络调用。
- 未知或模拟数据保留真实来源标签；没有实际字段时显示“未知”或不展示，不能填入虚构数据。
- 长设备名和状态支持换行或可访问的截断；文字放大、键盘焦点、屏幕阅读器和触控目标保持可用。

## 5. 验证与交付

### 5.1 验收用例

| 类型 | 输入 / 操作 | 通过标准 |
| --- | --- | --- |
| 首页视觉 | 空列表、1 台、多台、长设备名；手机与桌面各取样 | 层级清晰，不再为普通列表堆叠玻璃和明显阴影；无裁切、重叠或页面级横向滚动 |
| 状态组合 | 在线、同步中、离线快照、实时中断、登录错误及其组合 | 状态语义与现有代码一致；离线/过期和控制只读可识别；重连和刷新入口可用 |
| 功能 | 站点切换、刷新、下拉刷新、添加、进入详情、返回、前后台恢复 | 动作正确；设备列表更新不丢焦点或无故跳动；无重复请求或意外命令 |
| 材质与动效 | liquid/frosted/solid、高对比、强制颜色、减少动画、光学组件不可用 | 首页可读、可操作；材质切换及回退有效；其他页面不受首页作用域污染 |
| 可访问性 | 320px、200% 文字放大、键盘焦点、屏幕阅读器可访问名称 | 触控目标、可见焦点与语义名称保留；状态不单靠颜色；对比度达到 3.3 节目标 |
| 跨页回归 | 首页切换到详情、AI、动态及返回 | 除共享导航所需定位外，其他页面的材质与交互未被首页样式意外改变 |
| 性能 | 同条件对比 50/200 设备首页加载、单设备更新、滚动、后台恢复；1000 设备压力场景 | 光学节点及前后时延达到第 8 节目标；不丢失数据、权限和命令状态；报告原始样本及环境 |

截图应覆盖 320/390 的手机尺寸及 1280 的桌面尺寸，包含正常、空、离线/错误、多设备与高对比状态。使用固定合成数据分别保存改前和改后图，人工查看信息层级；截图审查不是对色彩或实际硬件性能的自动证明。允许对外观基线按设计审查更新，但不能删除或放宽原有安全、交互和无障碍断言来掩盖回归。

现有 `material-contract.spec.js` 部分断言明确要求旧版模糊、背景或布局，应先逐条判断是否针对本阶段首页：仅被批准改变的首页视觉契约按新方案更新；其他页面的原有契约，以及对比度、触控、焦点和状态安全断言继续保留。`motion-preview-visuals.spec.js` 目前导出截图，本身不等于自动图像差异验收。

### 5.2 现有测试入口

在 `apps/client-glass-next` 下执行：

```bash
npm test
npx playwright test e2e/glass-client.spec.js e2e/material-contract.spec.js e2e/mobile-client.spec.js e2e/mobile-offline-recovery.spec.js e2e/refresh-stability.spec.js e2e/bottom-navigation-motion.spec.js
npm run build
```

如首页作用域影响动效或局部渲染，再运行对应 `motion-states`、`motion-render-integrity`、`motion-interruptions` 等现有测试。实际变更后核对所有受影响测试，不可因预计执行时间而跳过失败。若新增样式有自动检查，应以用户可感知的行为、状态和可访问性为重点，避免只断言新 CSS 数值。

用户要求采用模拟替代实机：首轮使用 Playwright 合成数据和浏览器视口；可选 Android 模拟器检查 WebView 和安全区。浏览器及模拟器均不证明实体 PDA 的戴手套触控、阳光下可读性或硬件性能，报告应单独标注。

### 5.3 交付物

1. Glass Next 设备首页实现，以及必要的测试和改前/改后截图。
2. 首页状态、材质、响应式及回归结果；记录执行环境、通过、失败和跳过数量，以及前后性能样本和优化幅度。
3. 未解决问题和与实机相关的模拟限制。
4. 待首页设计方向确认后，再形成设备详情、动态和 AI 页的独立整改范围。

## 6. 执行顺序

1. 冻结现有首页关键状态的合成数据与截图，并按第 8 节测量修改前的性能基线。
2. 完成首页作用域、列表视觉和性能优化；检查局部更新、页面切换和降级模式。
3. 复测手机、桌面、异常状态、跨页回归和性能门槛，修复问题并重复同条件对照。
4. 对照本方案审核截图与测试证据，先交付首页供确认；确认后再讨论下一页面。

## 7. 方案审核

独立源码审查确认视觉方案覆盖首页、交互状态、无障碍和启动页边界；示例色值的纯白背景对比度及列出的重点 Playwright 文件均已核对。审查提出的首页画布残留渐变、双列断点冲突、光学节点创建时机已补入开发与验收要求。性能与安全独立复审未发现阻断问题；其对冷启动、计时、噪声和安全状态的建议已补入第 8 节。实际效果与性能提升需在开发后另行验证。

## 8. 性能优化：必达开发任务

### 8.1 当前已发现的潜在开销

以下为源码线索，尚不是耗时实测结论：

| 路径 | 当前实现 | 整改方向 |
| --- | --- | --- |
| `glass-surfaces.js` 和 `liquid.css` | 设备行、普通按钮自动添加 `liquid-glass`，同时使用 `backdrop-filter` | 首页普通设备行和按钮在构造时不创建光学子节点，不只用 CSS 隐藏；导航保留少量效果，其他页面不受影响 |
| `glass-appearance.js` | 观察整个根节点的子节点、class 和 style 变化，调度后扫描光学节点并读取导航几何 | 先通过计数/时间确认热点；再过滤无关变化或缩小观察范围，合并同帧工作、先读后写；新节点、尺寸、材质、前后台及销毁仍正确 |
| `ui.js` 的 `patchDeviceList` | 局部更新仍会扫描设备和节点；`desiredRefs.includes` 在大量设备时可能出现平方级比较 | 将实体匹配和集合比较改为经验证的索引/线性逻辑，避免循环中重复转换；覆盖别名、重复/缺失标识、增删和重排，保持在线数、焦点与滚动 |
| 初次设备列表 | 当前构造全部设备行 | 先测 1000 台合成设备；仅在数据证明需要时评估分页或虚拟列表，并单独设计搜索、焦点、屏幕阅读器和实时更新，不作为首版默认改造 |

现有 `render-coordinator.js` 已对普通更新合批、遥测约按 1 秒呈现最新值，并处理后台与失败回退。优化应复用它，不能再随意延长节流。权限撤销、站点切换、离线只读、设备状态失效、命令 ACK/失败和按压取消必须及时生效；中间遥测可按现有策略合并，最终状态不可丢失。

### 8.2 改前基线和测试环境

在改代码前固定当前代码提交、依赖锁文件、测试脚本和合成数据；对比两版使用同一主机、浏览器版本、窗口大小、CPU 限速、网络拦截、材质和电源条件。先分别记录未限速及模拟 4 倍 CPU 限速；4 倍只是一种压力模拟，不等同某款手机/PDA。

- 使用 `npm run build` 的生产构建及本地 preview，Playwright 拦截 API/WebSocket 并提供固定合成数据，不连接正式服务器、不下发真实命令；只运行一个 worker。基线和候选构建使用隔离目录或受控工作树，保存构建产物哈希，不覆盖用户的 Android 输出或既有结果。原有开发预览与 `__iotUiMetrics` 可用于定位，但默认不暴露到生产构建，不能把 dev 与生产构建数值混算。
- 固定 0、50、200 台设备进行首页测试；1000 台作为边界压力测试，不视为产品容量承诺。设备 ID、名称、状态、更新时间与事件序列使用固定种子。
- 场景覆盖首次进入且设备可见、首页返回、单设备状态更新、20 台状态批量更新、连续遥测、设备列表滚动和前后台恢复；另测缓存/实时故障与权限变化的正确性。
- 分别记录冷启动和热运行；冷启动每个样本使用新的浏览器上下文并清空浏览器侧测试缓存，不声称清空了宿主操作系统缓存；热运行单独预热至少 5 次。各主要时延在三轮独立运行中每轮收集不少于 30 个样本，报告 p50/p95、最小/最大、样本数、设备数、视口、浏览器、CPU 限速和代码身份。p95 统一使用排序后的最近秩法；前后版本交替执行，比较三轮统计值的中位数，测量失败或超时记录为失败，不从样本中静默剔除。若无法区分改进与噪声，标记不确定并重测。
- 指标包括：首批设备可见时间、更新输入到对应状态可见时间、点击到两次绘制机会的代理时间、滚动时长任务（超过 50ms）次数/总时长、帧间隔分布、普通列表光学节点数量；还可单独用开发诊断记录全量渲染、区域 patch、DOM 替换与网络请求数。浏览器不支持的内存/帧指标标为“不可用”，不能记作 0。
- 0 台设备单列“空状态可见时间”，不计入首批设备指标。输入/点击时记录浏览器单调时钟，等待目标 DOM 状态可见后再等待两次 `requestAnimationFrame`；所得值只代表绘制机会的代理指标，不宣称真实屏幕已显示。滚动脚本固定距离、速度、次数和起点（例如 1000 CSS px、2 秒、每轮 3 次），不足滚动距离的场景标记不适用；前后台用可重复的浏览器生命周期模拟并记录其与原生系统的差异。
- 新增的性能脚本应先断言所有非本地请求被拦截，保存其版本、运行命令、锁文件与浏览器版本、事件时序和失败情况；基线与候选分别写入 `artifacts/home-performance-20261030/` 下不同目录，避免覆盖。生产构建的性能测量不能直接复用只存在于 dev 的 fixture 模块。
- 现有 `e2e/runtime-load.spec.js` 主要模拟隔离后端的设备创建、API 及 WebSocket，需要专用测试服务并会写入测试设备；它不是首页渲染性能基线，不能指向正式环境。

### 8.3 暂定量化目标与门禁

以下是这次**模拟环境的开发目标**，不是已经测得的结果或生产 SLA。先取得基线，若同机重复基线波动过大，记录异常并解决环境问题后再比较，不能用一次偶然结果宣称达标。

1. 对 50/200/1000 台合成设备，首页设备列表行与普通列表按钮内的 `liquid-glass` 光学节点为 **0**；首页导航允许固定数量的光学节点。统计各材质模式和无光学组件回退，不以把节点 CSS 隐藏作为通过。
2. 对 200 台设备场景，首批设备可见和 20 台批量更新分别比较 p95：基线 ≥20ms 时目标至少降低 10%，且绝对降低至少 2ms；基线 <20ms 时要求不高于基线 +2ms。单设备更新和点击到两次绘制机会的代理时间 p95 不得高于基线加上 2ms 或 5% 中较大值，记录实际变化；这些指标可能受到帧周期和现有合批影响，不应为追求数字而改变安全语义。必须同时给出 p50 和原始样本；若不达标，继续分析或明确列为未完成。
3. 相同脚本条件下，三轮滚动长任务总时长及次数的中位数不得较基线增加；对现有稳定性测试的同一组重复事件，不增加数据发布或无效 DOM 替换；同一批次不引入额外全页面重建或重复网络请求。不得为满足计数而丢弃需保留的业务事件。若长任务结果受环境噪声影响无法判断，增加重复测量并标记不确定，不能记作通过。
4. 同一条件比较保留页面切换、离线/权限和命令反馈。以相同注入时点测量权限撤销、离线只读和命令 ACK 生效，优化后不得新增节流，时延不得超过基线加上测量误差；后台恢复时必须呈现最新状态并阻断不允许的命令，不能使用 1Hz 遥测阈值衡量这些安全状态。优化后不得丢失最终数据、焦点和滚动位置。1000 台压力场景不能出现脚本异常、页面崩溃或错误地执行/重发命令，记录实际时延而不宣称其已满足生产容量。
5. 性能门禁结果、视觉验收和既有回归测试均通过，才可标记首页整改完成。若测量手段不支持某指标，单列“未验证”，不能将其自动视为通过。

### 8.4 性能与功能回归

除第 5 节测试外，重点验证：权限撤销/切站时旧响应不能污染新上下文；离线转只读后恢复不自动重发；pending、sent、ACK、失败与未确认的顺序和最终状态准确；按压过程中失权或值变化取消旧意图；拖动滑块时及时体现只读；设备增删、重排、跨站同 ID、缺失引用不产生旧数据或错误计数。新建的性能用例和临时计数只能处理合成数据，不能默认在生产打印敏感信息。

2026-10-30 已在隔离浏览器配置下运行 `e2e/refresh-stability.spec.js`：**12 通过、0 失败**，覆盖重复事件、局部更新、按压与 1Hz 最新遥测呈现等。这是整改前的功能稳定性检查，**不是**首页时延、帧率或性能改善的数值基线。日志输出位于本地 `artifacts/home-performance-20261030/baseline/`。
